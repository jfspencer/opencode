Why we rewrote our build in a weekend

Spoiler: we didn't really do it in a weekend.

Sam Example

2 Nov 2024• 9 min read

Last month our CI times crossed forty minutes. That's forty minutes between "I pushed a fix" and "I know whether the fix works". Something had to give.

This post walks through what we changed, what we measured, and — most importantly — what we got wrong along the way. If you only read one section, read What went wrong.

The old setup

The old pipeline was a 2,300-line Makefile that had grown organically since 2016. Some highlights:

  • Every target depended on clean, so nothing was ever cached.
  • Tests ran serially because two of them shared a port (:8080, of course).
  • A step called fix-permissions ran chmod -R 777 . — don't ask.

"A build system is a program that runs other programs, badly."
— an anonymous colleague, after a long night

Measuring first

Before changing anything we added timing to every step. The results were... instructive:

StepMedianp95
Dependency install6m 12s11m 40s
Compile14m 03s15m 30s
Unit tests9m 47s12m 02s
Integration tests8m 55s19m 10s

Notice the p95 for integration tests: almost all of that variance came from one flaky test that retried five times with exponential back-off.

The rewrite

We moved to a content-addressed cache. The core idea fits in a few lines:

def cache_key(step, inputs):
    h = hashlib.sha256()
    h.update(step.command.encode())
    for path in sorted(inputs):
        h.update(path.encode())
        h.update(digest(path))
    return h.hexdigest()

if (key := cache_key(step, step.inputs)) in cache:
    restore(cache[key])  # <-- the 90% case
else:
    run(step); cache[key] = snapshot(step.outputs)

That's it. Everything else is plumbing: remote storage, eviction, and making sure inputs is actually complete.

What went wrong

  1. Undeclared inputs. The compiler read $HOME/.config/toolchain.toml. Nobody knew. Cache hits produced binaries built with the wrong flags.

  2. Timestamps in outputs. Our archives embedded mtime, so identical inputs produced different outputs, which defeated downstream caching.

  3. The 777 step. Yes, it came back to bite us: file modes were part of the digest.

    • Fix: normalize modes to 0644/0755 before hashing.
    • Second fix: delete the step. Nobody missed it.

Results

Median CI time is now 6m 40s (down from 39m). Cache hit rate sits around 87%. Developers have stopped making coffee during builds, which has been bad for the coffee machine's utilization metrics.
